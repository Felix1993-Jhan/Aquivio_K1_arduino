## 1. 系統定位

K1 由**上位機**(觸控螢幕軟體 `aquivio-touch-react`)與 **Arduino Mega 2560(本韌體)**組成,以 USB 序列埠溝通。上位機負責介面與配方;韌體負責泵、閥、slot(營養液泵)、UVC 的開關,以及流量計計數與到量判斷。

K1 韌體有兩個版本,分在兩條分支:

| 版本 | 分支 | 協定 | 搭配的上位機 |
|---|---|---|---|
| **K1 JSON 版(本文件)** | `main-v4` | 文字命令 + JSON,以 `#` 結尾,9600 baud | K1 上位機 |
| K2 移植版 | `main-k2port-v4` | K2 二進位封包(`40 71 30` + checksum),115200 baud | K2 上位機 |

共用模組(`pins`、`tick`、`flowmeter`、`pressure`、`tx_queue`、`diagnostics` 的心跳)在本分支修正,再合併到 K2 移植版;不反向合併。

## 2. 與原 K1 韌體的差異

行為基準是現場最新版 `mcu31v2`。命令格式與回覆字串維持相容,內部改寫如下:

| 項目 | 原 K1 | 本版 |
|---|---|---|
| 計時 | `millis()` + `delay()`,出杯中整個 `loop()` 卡住 | Timer5 每 1 ms 一個 tick,工作在主迴圈補跑,**不阻塞** |
| 出杯中收命令 | 收不到(要等出杯結束) | `stop`、`stopslotN`、`pressure` 立刻處理,其他暫存到 `end` 之後 |
| GPIO | `digitalWrite` | 直接存取暫存器(`PinMap[]`) |
| 輸出 | `Serial.print`(緩衝滿時空等) | TX 佇列(512 byte),不等待 |
| 流量計 | PCINT 中斷計上升緣 | 每 1 ms 取樣,高 / 低各連續 3 ms 才確認(debounce,同 K2) |
| 數值 | 浮點、`String` | 整數(水量 µL、時間 ms),不用 `String` |
| 命令解析 | 緩衝滿會永久卡死、多筆黏在一起會全部遺失 | 逐 byte 解析,讀到 `#` 處理一筆;超過 255 字元丟棄該筆後自動恢復 |
| 120 秒逾時 | 16-bit 溢位,實際約 49.7 天才生效 | 修正為 120 秒 |
| 新增 | — | A1 水壓 ADC(`pressure#`)、D23 心跳、freeflow(第 6 節)、〔暫時〕D66 同步流量計 |

## 3. 架構

### 3.1 執行模型

```
Timer5 中斷(每 1 ms)  tick_cnt++、流量計取樣 + debounce(除錯版另產生 D22 模擬波形)
主迴圈 loop()
  ├ tick_service()     欠幾個 tick 就補跑幾次 tick_main()
  ├ diag_poll()        待機時:mcuAlive(每 1 秒)、記憶體檢查(每 30 秒)
  ├ cmd_poll()         逐 byte 讀命令,讀到 '#' 處理一筆
  └ tx_poll()          TX 佇列搬到 Serial(有空位才搬,不等待)
```

- 中斷只做計數與取樣;所有寫輸出腳位的動作都在主迴圈(Port K 的讀改寫不是原子操作)
- 主迴圈晚了,tick 不會漏,只會晚做後連續補跑

### 3.2 `tick_main()`(每 1 ms,依序)

| 順序 | 函式 | 做什麼 |
|---|---|---|
| 1 | `diag_tick_1ms()` | mcuAlive / 記憶體檢查計時;D23 心跳每 1 秒翻轉 |
| 2 | `diag_flow_mirror_1ms()` | 〔暫時〕D66 跟著流量計 A8 的電位(看 LED 用) |
| 3 | `dispense_tick_1ms()` | 出杯狀態機:slot 倒數、到量 / 最短時間、逾時、Progress |
| 4 | `jff_tick_1ms()` | freeflow:流量累積、slot 開關、每 200 ms 回報 pulse |
| 5 | `pressure_tick_1ms()` | 水壓:每 200 ms 啟動一次 ADC,下一個 tick 收值 |

### 3.3 模組

程式都在 `mcu/` 根目錄(Arduino IDE 只看 sketch 資料夾根目錄)。

| 模組 | 內容 | 共用 |
|---|---|---|
| `pins` | 腳位表 `PinMap[]`、暫存器讀寫 | ✅ |
| `tick` | Timer5 1 ms tick、`tick_main()` 分派 | ✅(分派內容各分支不同) |
| `flowmeter` | 流量計 1 ms 取樣 + debounce、除錯版 D22 模擬波形 | ✅ |
| `pressure` | A1 水壓 ADC | ✅ |
| `tx_queue` | TX 發送佇列 `out` | ✅ |
| `diagnostics` | 看門狗、D23 心跳、D66 同步;本分支另有 mcuAlive、記憶體檢查 | 部分 |
| `uart_cmd` | 命令解析與分派、出杯中命令暫存 | 本分支 |
| `dispense` | JSON 出杯(解析層 + 1 ms 狀態機) | 本分支 |
| `jsonfreeflow` | freeflow(第 6 節) | 本分支 |
| `device` | 水路、slot 開關與輸出字串 | 本分支 |
| `MemoryFree` | 剩餘 SRAM 計算 | 本分支 |

## 5. 通訊協定

### 5.1 序列埠

| 項目 | 內容 |
|---|---|
| 參數 | 9600 baud、8N1、無流量控制 |
| 開 port | 板子會自動重開(16U2 的 DTR 接 RESET),所有輸出回到關閉;收到一行 `ready` 之前不要送命令 |
| 送出 | ASCII,每筆以 `#` 結尾,不加換行;可以一次送多筆(`ping#ping#`) |
| 長度 | 不含 `#` 最多 255 字元,超過整筆丟棄 |
| 接收 | 以 `\n` 分行,去掉行尾 `\r` 與空白;判斷時用**整行比對** |
| `mcuAlive` | **只在待機時**每 1 秒一行;出杯 / freeflow 中不送,`end` 之後恢復 |

### 5.2 命令

除了 `ping`,每個命令都會先回傳命令本身一行。

| 命令 | 動作 | 回覆(待機時) |
|---|---|---|
| `ping#` | — | `pong` |
| `startslotN#`(N = 1~10) | 開 slot N,一直開著直到關掉 | `startslotN` |
| `stopslotN#` | 關 slot N | `stopslotN` |
| `startcoldwater#` / `startwarmwater#` | 開水泵 + 冷水 / 常溫閥(互斥),一直開著、沒有逾時 | 命令本身 |
| `stop#` | 關水路與全部 slot | `stop`、`pulse:<N>`、`cold water usage:<x.xxx>`(或 `warm`);不印 `end` |
| `pressure#` | 讀 A1 水壓(ADC 原始值,每 200 ms 更新) | `pressure`、`pressure:<0~1023>`;開機約 200 ms 內為 `pressure:null` |
| JSON + `#` | 有 `"freeflow"` 鍵 → freeflow(第 6 節);否則 → 出杯(5.3) | 見各節 |

韌體不認得的字串會被當成 JSON → 回 `start`、`Received actions: …`、`Failed to parse JSON: …`,沒有 `end`。

### 5.3 出杯 JSON

```json
{"cold":"0.30","time":4500,"slot3":"1500.00","slot7":"800.00"}
```

| 鍵 | 型別 | 說明 |
|---|---|---|
| `cold` / `warm` | 字串(公升),也接受數字 | 目標水量;兩個都有時 cold 優先。`"0"` = 不看流量計。沒有這個鍵 = 不出水 |
| `time` | 數字(ms),選用 | 最短出水時間:到量**且**滿 `time` 才停水 |
| `slot1`~`slot10` | 字串(ms),也接受數字 | 開啟時間,小數截掉;有這個鍵就會開 |

- 到量判斷為「累計 ≥ 目標」,1 pulse = 3.3 ml
- slot 依時間**由長到短**開(相同時編號大的先),每 250 ms 開一個,各自準時關閉
- 120 秒逾時(從 slot 全開完起算)

回覆順序:

```text
{"cold":"0.30","slot3":"1500.00"}          ← 命令本身
start
Received actions: {"cold":"0.30","slot3":"1500.00"}
Cold water flow requested: 0.30            ← 沒有水時為 No water flow requested
Activated slot 3 for duration: 1500        ← 每個 slot 一行,間隔 250 ms
Progress - Accumulated flow: 0.12 / Desired flow: 0.30    ← slot 全開完後每秒一行
Deactivated slot 3
Stopping water pump (volume & time satisfied).
pulse:91
cold water usage:0.300
pulse:0                                    ← 收尾再印一次(固定為 0)
cold water usage:0.000
Deactivated slot 1 … Deactivated slot 10   ← 收尾:slot 1~10 各一行
finish: stopped by flow pulse threshold
end
```

| `finish:` 行 | 情況 |
|---|---|
| `stopped by flow pulse threshold` | 到量停水 |
| `stopped by minimum time constraint` | 先到量,等 `time` 滿才停 |
| `stopped by (volume & time) unspecified` | 其他到量情況 |
| `stopped by system timeout or external stop` | `stop#`、120 秒逾時(前面有 `ERROR: Execution timeout reached`)、水量 `"0"` 或不出水 |

### 5.4 出杯 / freeflow 中送命令

| 命令 | 處理 |
|---|---|
| `stop#` | **立刻**收尾(印 `finish`、`end`) |
| `stopslotN#` | **立刻**關該 slot(出杯中還沒輪到開的取消不開;freeflow 中本次不再開) |
| `pressure#` | **立刻**回覆 |
| 其他(`ping`、`startslotN`、新的 JSON…) | 暫存(256 byte),`end` 之後依序執行 |

### 5.5 其他可能出現的行

| 行 | 說明 |
|---|---|
| `ready` | 開機 |
| `New lowest memory: <N> bytes` | 剩餘 SRAM 創新低 |
| `WARNING: Very low memory!` | SRAM 過低 |

## 6. freeflow(按住出水)〔暫定〕

按住出水、放開停止;slot 依**實際流量**按比例開啟,一杯多少水由上位機決定(上位機看回報的 pulse 數,到量就送 `stop#`)。演算法與 K2(`0x07` LONG_PRESSURE)相同。程式:`mcu/jsonfreeflow.cpp/.h`。

### 6.1 命令

```json
{"freeflow":"cold","slot1":24,"slot3":50}
```

| 鍵 | 型別 | 說明 |
|---|---|---|
| `freeflow` | 字串 | `"cold"` = 冷水、`"warm"` = 常溫水;其他值 → 不啟動 |
| `slot1`~`slot10` | 數字或字串 | **每 1 個流量 pulse,該 slot 要開幾 ms**;小數截掉,上限 150,0 = 不用 |

- 不帶 slot = 只出水(同 K2 的沖洗)
- 沒有目標水量、沒有逾時;結束只靠 `stop#`
- slot 值的算法(由上位機換算):`每 pulse ms = 整杯 slot ms × 3.3 ml ÷ 整杯水量 ml`,例:300 ml 配 2181 ms → 2181 × 3.3 ÷ 300 ≈ 24。韌體內已寫好同樣的換算函式 `jff_add_from_recipe()`(方案 A,目前未使用)

### 6.2 動作

1. 開水泵 + 對應水閥、開 UVC(A9 / A10)
2. 每來 1 個 pulse:各 slot `acc += 時間值`(上限 250)
3. `acc ≥ 100` → 開 100 ms、扣 100;扣完仍 ≥ 100 就繼續開,< 100 才關
4. **錯開**:有設定的 slot 依編號由小到大,`acc` 起點輪流 17 / 50 / 83 → 同比例的 slot 不會同時開(減少出水口的噴水感);平均預加 50,抵掉結束時的殘量
5. `stop#`:全關(slot、UVC、水泵、水閥)

### 6.3 回覆

```text
{"freeflow":"cold","slot1":24,"slot3":50}  ← 命令本身
start
Received actions: {"freeflow":"cold","slot1":24,"slot3":50}
Freeflow cold requested
freeflow pulse:1                           ← 每 200 ms 一行:本次開始後累計的 pulse 數
freeflow pulse:2
…
stop                                       ← 收到 stop#
pulse:30                                   ← 本次總 pulse 數(≥ 最後一行回報)
cold water usage:0.099
finish: freeflow stopped by external stop
end
```

- `freeflow pulse:N` 是累計值,中間漏一行不影響;換成 ml 由上位機算(× 3.3)
- freeflow 中不印 `Progress`、不送 `mcuAlive`
- `freeflow` 值錯誤:`Failed to parse JSON: freeflow`,不啟動、沒有 `end`

## 7. 正式版與除錯版

差別全部由編譯開關 `K1_DEBUG_FLOW_GEN` 控制(原始碼預設關閉):

| 項目 | 正式版 | 除錯版 |
|---|---|---|
| D22 | 不動 | 水泵開著時輸出約 6 Hz 方波(模擬流量計,杜邦線接 A8) |
| freeflow `stop` | 如 6.3 | `finish` 前多兩行統計:`freeflow stat slot ms: 1=693 3=1485`(各 slot 實際開啟 ms)、`freeflow stat open: 0=3074 1=1584 2=297`(同時開 0、1、2… 台的累計 ms) |
| 用途 | 上機(真的流量計) | 空板測試 |
| 大小(Flash / RAM) | 19298 / 2543 byte | 19884 / 2674 byte |

另有 `K1_DEBUG_TICK`(`tick.h`,預設關閉,除錯版也不開):每秒在 `mcuAlive` 後印 `tick backlog max: <N>`(主迴圈最多積欠幾個 tick)。

## 8. 建置、燒錄、測試

在 `mcu/` 下執行(arduino-cli 不在 PATH):

```bash
# 正式版
arduino-cli compile --fqbn arduino:avr:mega:cpu=atmega2560 -u -p <COM> .
# 除錯版
arduino-cli compile --fqbn arduino:avr:mega:cpu=atmega2560 --build-property "compiler.cpp.extra_flags=-DK1_DEBUG_FLOW_GEN" -u -p <COM> .
```

- 正式版 / 除錯版互相切換時加 `--clean`
- 燒錄前先關掉上位機(會佔住 COM port)
- 空板測試用除錯版;上機用正式版

測試腳本在 `tools/`,清單、接線與最後驗證結果見 [tools/README.md](../tools/README.md)。freeflow 為 `tools/k1_freeflow_test.py`(除錯版 + D22 → A8)。
