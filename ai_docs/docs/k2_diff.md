# K1 K2 移植版與 K2 韌體的差異

> **這份文件做什麼**:記錄 K1 K2 移植版(`main-k2port-v4`)與 K2 韌體哪裡不一樣，以及為什麼不一樣。
> - 給誰看:要同時看 K1、K2 兩份程式的人，或要把 K2 的修改同步到 K1 的人
> - 怎麼用:K2 改版時，對照第 2~5 節，判斷那個修改 K1 要不要跟、能不能跟;K1 改了與 K2 不同的行為時，也記在這裡
> - 不在這裡:兩邊相同的部分(協定細節見 [protocol.md](protocol.md))
>
> 對照基準:K1 0.0.4.0(`b74d5a3`)↔ K2 v0.0.0.11(K2 repo `405f779`,2026-11-12)。〔[沿革](#沿革)〕

## 1. 一句話總結

K1 硬體做得到的 K2 功能都已移植，上位機可沿用 K2 的命令與裝置 ID。差異分成三類：

- K1 沒有的硬體 → 回不支援格式(第 2 節)
- K1 刻意不同的行為(第 3 節)
- K1 修正、K2 尚未修正的問題(第 4 節)

## 2. K2 有、K1 沒有的功能

| K2 功能 | K1 處理 | 原因 |
|---|---|---|
| `0x08` ERROR_REPORT 異常偵測(裝置電流、空轉 DRY_RUN、短脈衝、漏水、溫度、壓力門檻) | 不支援格式;請求仍依 K2 長度(7 / 16 byte)收完 | 沒有電流、溫度、漏水感測 |
| `0x09` MAX30102 心跳 / 血氧 | 不支援格式 | 沒有此硬體(K2 自己也停用) |
| `0x0A` WATER_MODE 水桶模式 / 自動補壓 / 強制補壓 | 不支援格式 | 需要水壓感測與水桶接法 |
| `0xB0` BOOTLOADER / OTA | 不支援格式 | K1 用 Arduino USB 燒錄 |
| `0x03` 讀裝置電流(ID 0~17、25)、壓力(19 / 20)、溫度(21~23)、漏水(24)、板版(0xF0) | 不支援格式 | 沒有這些感測器;A1 水壓 ADC 程式保留但不對外 |
| `0x06` / `0x07` Type 2 氣泡水(ID16、freeflow 模式 2、500 ms 週期、氣泡水錯開) | 不支援格式 | K1 沒有氣泡水 |
| ID10 水泵 TIM3 PWM | 開關 | K2 實際也只用 0 / 100% |
| ID11 UVC0、ID16、ID17 Clean、ID25 Container | `Status` 照翻,無腳位輸出 | K1 沒有對應硬體 |
| DS18B20、ADG715、VREFINT、`pid_ctrl`、`tx_fuzz` | 不移植 | 硬體或用途不存在 |

## 3. K1 刻意與 K2 不同的地方

| 項目 | K2 | K1 | 原因 / 決定 |
|---|---|---|---|
| 不支援功能的回覆 | 各命令不同(讀不到回 0、0x09 回 0 筆…) | 一律 9 byte `[代碼] FF [代碼] FF` | 上位機能分辨「不支援」與「值為 0」(使用者 2026-11-11) |
| `0xB5` 狀態查詢 | 無 | K1 自訂:`SUB 00` = `Status`、`01` = 實際腳位 | 測試用;正式版是否保留〔待定〕 |
| `0x07` UVC | 只開 0x07 有帶的 ID11~13;N = 0 沿用上一包 | Type 0 / 1 一律開 ID11~13 | 上位機不帶 UVC,沖洗又在 `0x02` 之後;UVC 要對出水殺菌(使用者 2026-11-12) |
| `0x07` N 上限 | 18(`COUNTER_SIZE`),不檢查 | 19,超過丟棄不回 | 收包緩衝 64 byte;見第 4 節 |
| PING 版本 | 0.0.0.11 | 0.0.4.0 | 版本各自編號 |
| 流量換算 | 韌體不換算 | 同 K2 | 每 pulse 的 ml 由上位機設定 |
| 流量 pulse 處理 | 流量計中斷內每 pulse 扣 1 / 累積 1 次 | 每 1 ms 讀總計數增量 `d`,一次處理 | 共用的 `flowmeter` 模組不改;結果相同 |

## 4. K1 修正、K2 尚未修正的問題

K2 欄為 2026-11-12(`405f779`)的狀態。「實際影響」依 K2 上位機 `aquivio-station`(2026-10-28 版)的用法判斷。

| 問題 | K2 現況 | 實際影響 | K1 |
|---|---|---|---|
| `0x07` 長度 `6 + 3N` 存 `uint8_t`,N ≥ 84 溢位繞回(例:N = 86 → 被當成 9 byte 收下,之後寫 86 組) | 未修 | 不會發生:上位機的 slot ID 限 0~10,N 最多 11 | 防呆:N > 19 丟棄 |
| `0x07` N > 18 寫出 `channel7_CMD[18]` 陣列外 | 未修 | 同上 | 防呆:陣列 19 筆,N 上限 19 |
| `0x06` 完成通知用 `createCS()`,以「最後收到那一包的長度」決定 CS 位置;那一包是 `0x07` / `0x08`(非 9 byte)時 CS 寫錯位置 | 未修 | 不會發生:`0x06` 出水期間上位機只送 9 byte 命令(`0x03` 讀流量、`0x01` / `0x02`、PING);`0x07` 只用在 freeflow,`0x08` 只在開機檢查與管理頁 | 獨立 9 byte 緩衝計算;K2 算對時兩邊送出的 byte 完全相同 |
| `1 << id` 在 AVR(16-bit `int`)會溢位 | K2 為 32-bit,無此問題 | — | `DEV_BIT(id) = 1UL << id` |
| `0x01` / `0x02` 遮罩 `RxBuffer[7] << 24` 在 16-bit `int` 溢位 | 同上 | — | 先轉 `uint32_t` 再移位 |

上位機收封包時會驗 CS,CS 錯的封包直接丟掉(`k2-worker.cjs` `attachRxParser`)。所以上位機沒有特別處理上面的問題，只是照目前的用法碰不到。

## 5. 兩邊已一致的修改

這些修改在 K1 與 K2 都已經做了，記錄由哪邊先提出，方便追溯。

| 修改 | 先做 | K2 跟進 |
|---|---|---|
| UART 標頭逐 byte 比對(雜訊後仍找得到開頭) | K1 P1 | v0.0.0.11 |
| freeflow 開 slot 條件 `acc > 100` → `≥ 100`(剛好 100 時卡開) | K1 P5 | v0.0.0.11 |
| freeflow slot 錯開開啟(acc 起點 17 / 50 / 83) | K1 P5 追加 | v0.0.0.11(另加氣泡水錯開) |

## 6. 兩邊相同的已知限制(照 K2,不修正)

| 限制 | 影響 | 決定 |
|---|---|---|
| `0x06` 出水中被 `0x02` 中斷,剩餘 `Pulse` 不清除 | 下次有水流時繼續扣,扣完多送一次完成通知 | 上位機畫面沒有停止鍵,只有定時 UVC 殺菌可能中斷，機率很小(使用者 2026-11-11 / 11-12) |
| 連續兩包 `0x07` 中間沒有 `0x02`:不清 `mSec_100count`、不關舊包獨有的 slot | 開啟中的 slot `acc` 下溢,下一個 pulse 被夾回 250,約多開 2~3 個 100 ms;舊 slot 開到 `0x02` | 只在結束封包遺失時發生(使用者 2026-11-12) |

## 7. 架構差異

| 項目 | K2 | K1 |
|---|---|---|
| MCU | STM32U073(Cortex-M0+,32-bit,48 MHz) | ATmega2560(8-bit,16 MHz) |
| 計時 | TIM1 1 ms 中斷內跑 `timer1_*` | Timer5 ISR 只計數 + 流量取樣;`timer1_*` 在主迴圈 `tick_main()` 補跑(方案 A) |
| 共用變數保護 | `__disable_irq` 交接 | 只在主迴圈存取,不需要 |
| 收包 | HAL UART 中斷逐 byte;處理中 `RX_OK` 鎖住丟棄新資料 | Arduino Serial 中斷收進 64 byte 緩衝,主迴圈逐 byte 取;收滿就處理,不需鎖 |
| 收發緩衝 | 256 byte | 64 byte |
| 回覆 | `HAL_UART_Transmit` 阻塞送出 | TX 佇列(512 byte),不等待 |
| 輸出 | HAL GPIO | 直接存取暫存器;擴充 I/O 區讀改寫非原子 → 只在主迴圈寫 |
| 裝置對照 | `DeviceMap[]` 存 GPIO port / pin | 存 K1 `PinMap` 索引 |

## 8. 同步 K2 修改時的檢查方式

1. 看 K2 `ai_docs/docs/changelog.md` 最新版本的「本版啟用 / 取消」
2. 判斷修改屬於哪一類:
   - 第 2 節功能(K1 沒有硬體)→ 不用跟
   - 第 5、6 節範圍 → 比對 K1 程式是否已一致
   - 協定或共用邏輯 → 照 K2 改，並在 [protocol.md](protocol.md) 更新
3. 改完更新本文件的對照基準(K1 commit ↔ K2 版本 / commit)
