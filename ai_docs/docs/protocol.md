# UART 通訊協定(K1 K2 移植版)

> 加入版本:0.0.4.0 / 最後修改:0.0.4.0(2026-11-12)
> 韌體 0.0.4.0(`main-k2port-v4`)。協定沿用 K2 v0.0.0.11(`ai_docs/docs/protocol.md`);標 ⚠ 的是 K1 與 K2 不同之處,總表見 [k2_diff.md](k2_diff.md)。
> 程式:`mcu/uart_cmd.cpp`(收包、分派、回覆)、`mcu/device_ctrl.cpp`(裝置 ID)、`mcu/timer_task.cpp`、`mcu/freeflow.cpp`。

## 1. 實體層

| 項目 | 內容 |
|---|---|
| 介面 | USB → 板上 16U2 → ATmega2560 UART0(D0 / D1) |
| 速率 | 115200 bps、8N1、無流量控制(上位機不可開 XON/XOFF;16U2 為透明 byte 橋接,0x00~0xFF 原樣傳送) |
| 開 port | 16U2 的 DTR 經電容接 RESET → **開 port 即重開機**,約 2 秒後才收命令(硬體行為,韌體無法關閉) |
| 主動送出 | 只有 `0x06` 到量完成通知;開機不送任何資料 |

## 2. 封包格式

```
[0x40] [0x71] [0x30] [CMD] [Data ...] [CS]
```

- **CS**:全包(含 CS)加總 & 0xFF = 0,即 `CS = −(前面所有 byte 總和) & 0xFF`
- **長度**:收到第 5 byte 時依 `CMD` 查表決定

| CMD | 長度(含 CS) |
|---|---|
| `0x00~0x06`、`0x09`、`0x0A`、`0xB0`、`0xB5` | 9 |
| `0x07` | 7 + 3N(N = `[4]`,上限 19 → 最長 64)⚠ |
| `0x08` | `[4] = 0x01` 為 16,其他 7 |
| 其他 | 不在表內 → 丟棄重收、**不回覆** |

### 2.1 收包規則

| 情況 | 處理 |
|---|---|
| 標頭 | ⚠ 逐 byte 比對 `40 71 30`;不符就丟掉該 byte,但若是 `0x40` 當成新封包第 1 byte(前面有雜訊也找得到開頭) |
| 逾時 | 從第 1 byte 起 20 ms 內沒收完 → 丟棄,下一個 byte 從頭收 |
| CMD 不在長度表 | 丟棄、不回 |
| `0x07` 的 N > 19 | ⚠ 丟棄、不回(超過 64 byte 接收緩衝) |
| CS 錯誤 | 回覆長度 = 請求長度,`[4]` 到 CS 前一 byte 全填 `0xFF`:9 byte 為 `40 71 30 [CMD] FF FF FF FF [CS]` |
| 連續封包 | 收滿一包立刻處理並回覆,後面的 byte 留在 Serial 緩衝接著收,不會遺失 |

## 3. 命令總覽

| CMD | 名稱 | K1 | 回覆 |
|---|---|---|---|
| `0x00` | SWITCH_SET | ✅ | 原封包 |
| `0x01` | SWITCH_START | ✅ | 原封包 |
| `0x02` | SWITCH_STOP | ✅ | 原封包 |
| `0x03` | SENSOR_READ | ✅ 只有 ID18 | `[4]` = ID,`[5..7]` = 讀值 |
| `0x04` | SENSOR_CLEAR | ✅ 只清 ID18 | 原封包 |
| `0x05` | PING | ✅ | 版本 |
| `0x06` | SET_PULSE | ✅ Type 0 / 1 | 原封包;到量另送完成通知 |
| `0x07` | LONG_PRESSURE | ✅ Type 0 / 1 | 原封包(7 + 3N) |
| `0x08` | ERROR_REPORT | ❌ | 不支援格式(第 5 節) |
| `0x09` | MAX30102_QUERY | ❌ | 不支援格式 |
| `0x0A` | WATER_MODE | ❌ | 不支援格式 |
| `0xB0` | BOOTLOADER | ❌ | 不支援格式 |
| `0xB5` | STATUS_QUERY | ⚠ K1 自訂 | 32-bit 狀態(第 6 節) |

以下封包範例皆為實際位元組(含 CS)。多 byte 數值一律 Little-Endian(低位在前)。

## 4. 各命令

### 4.1 裝置 ID 與位元遮罩

`0x01` / `0x02` / `0xB5` 的 32-bit 遮罩:bit n = ID n。ID 對照見 [hardware.md 第 3 節](hardware.md#3-裝置-id-對照)。

| ID | 裝置 | K1 |
|---|---|---|
| 0~9 | slot1~10(營養液泵) | ✅ |
| 10 | 水泵 | ✅(K2 為 PWM,K1 開關) |
| 11 | UVC0 | 無實體:Status 照翻,無腳位輸出 |
| 12 / 13 | UVC1 / UVC2 | ✅ A9 / A10 |
| 14 / 15 | 常溫閥 / 冷水閥 | ✅ |
| 16 / 17 / 25 | 氣泡水閥 / Clean / Container | 無實體:Status 照翻,無腳位輸出 |
| 18~24 | 感測器 ID | 不是輸出裝置,遮罩中忽略 |

### 4.2 `0x00` SWITCH_SET — 單一裝置定時開啟

```
請求:40 71 30 00 [ID] [T0] [T1] [T2] CS     T = 24-bit 毫秒
例  :40 71 30 00 00 E8 03 00 34               slot1 開 1000 ms
回覆:原封包
```

- `ID` 不是輸出裝置 → 不動作,仍回原封包
- `T = 0`:開啟後不自動關(同 K2)
- 倒數每 1 ms 減 1,到 0 時關閉;**freeflow 中倒數暫停**(同 K2)
- 同一 ID 再送一次會覆寫剩餘時間

### 4.3 `0x01` / `0x02` SWITCH_START / STOP — 遮罩開關

```
請求:40 71 30 01 [M0] [M1] [M2] [M3] CS      M = 32-bit 遮罩
例  :40 71 30 01 01 04 00 00 19               開 slot1(ID0)+ 水泵(ID10)
回覆:原封包
```

- `0x01`:遮罩內未開的裝置打開(不設倒數)
- `0x02`:遮罩內開著的裝置關閉,並清除其 `0x00` 倒數
- `0x02`:若正在 freeflow,**不論遮罩內容**先結束 freeflow(清除所有 slot 資料)
- 上位機的 freeflow 結束封包:`40 71 30 02 FF FF 03 00 1C`(bit 0~17)

### 4.4 `0x03` / `0x04` SENSOR_READ / CLEAR — 流量

```
讀取:40 71 30 03 12 00 00 00 0A               ID18 流量
回覆:40 71 30 03 12 [P0] [P1] [P2] CS         P = 流量 pulse 數(低 24 bit)
例  :40 71 30 03 12 19 00 00 F1               25 pulse
歸零:40 71 30 04 12 00 00 00 09 → 回原封包
```

- 只有 ID18 有值。韌體只回 pulse 數,不換算 ml(換算由上位機做)
- `0x03` 其他 ID(0~17、19~25、0xF0、未定義)→ 不支援格式 `[ID] FF [ID] FF`,例 ID20:`40 71 30 03 14 FF 14 FF F6`
- `0x04` 只有 ID18 會歸零;其他 ID 不動作,回原封包(同 K2)
- 流量計數為開機起累計,只有 `0x04` 會歸零

### 4.5 `0x05` PING

```
請求:40 71 30 05 00 00 00 00 1A
回覆:40 71 30 05 00 04 00 00 16               [4..7] = VERSION0~3 → 0.0.4.0
```

### 4.6 `0x06` SET_PULSE — 依流量脈衝數出水

```
請求:40 71 30 06 [Type] [P0] [P1] [P2] CS     P = 24-bit pulse 數
例  :40 71 30 06 01 68 00 00 B0               冷水 104 pulse
回覆:原封包
完成:40 71 30 06 [Type] 01 00 00 CS            MCU 主動送
例  :40 71 30 06 01 01 00 00 17
```

| Type | 開啟 |
|---|---|
| 0 | 常溫:水泵 ID10 + 常溫閥 ID14 |
| 1 | 冷水:水泵 ID10 + 冷水閥 ID15 |
| 2 以上 | ⚠ 不支援格式 `[Type] FF [Type] FF`,不動作(K1 沒有氣泡水) |

- 每來 1 個流量 pulse 減 1;減到 0 → 關閉該 Type 打開的裝置,並送完成通知
- `P = 0`:不倒數,一直開到 `0x02`
- 不開 UVC;一般出杯由上位機另以 `0x01` 開 UVC
- 已知行為(同 K2,不修正):出水中被 `0x02` 中斷時剩餘 pulse 不清除,下次有水流時會繼續扣並送出一次非預期的完成通知。上位機目前的用法不會發生

### 4.7 `0x07` LONG_PRESSURE — freeflow 常壓連續出水

```
請求:40 71 30 07 [N] ([ID] [T0] [T1]) × N [Type] CS     長度 7 + 3N
     T = 該 ID 每 1 個流量 pulse 要開幾 ms(16-bit)
例  :40 71 30 07 01 00 32 00 01 E4            冷水,slot1 每 pulse 50 ms
沖洗:40 71 30 07 00 00 18                     N = 0,常溫
回覆:原封包
```

| Type | 開啟 |
|---|---|
| 0 | 常溫:水泵 + 常溫閥 + UVC ID11~13 |
| 1 | 冷水:水泵 + 冷水閥 + UVC ID11~13 |
| 2 以上 | ⚠ 不支援格式 9 byte,不動作 |

**N > 0**:記錄每組 ID 與時間值,依 ID 由小到大排序,進入 freeflow。

- ID 0~9(slot):時間值上限 150 ms(超過以 150 計)
- ID 11~13(UVC):時間值不使用
- 其他 ID:記錄但不動作

**N = 0**:停料、只出水。

1. 關閉 slot、水泵、常溫 / 冷水 / 氣泡水閥(ID 0~10、14~16),清除 slot 資料
2. 依 Type 重開水泵 + 閥

**UVC** ⚠:Type 0 / 1 一律開 ID 11~13,不論 0x07 有沒有帶、N 是多少。

- 原因:K2 上位機的 0x07 不帶 UVC ID;沖洗 `07 00 00` 又是在 `0x02` 結束之後才送。照 K2 寫法,出水時 UVC 都不會開
- 關閉:由上位機的 `0x02` 結束封包關閉

**slot 開啟規則**(每 1 ms 處理,程式在 `freeflow.cpp`):

```
每 1 個流量 pulse:acc += 時間值                 (上限 250)
acc ≥ 100 且 slot 未在計時 → 開 slot,開始計時
計時滿 100 ms → acc −= 100;剩 < 100 才關,否則繼續開 100 ms
```

- slot 開啟時間 ≈ pulse 數 × 時間值。每扣 100 實際開 99 ms,約少 1%
- 放開(`0x02`)時,acc 剩下不到 100 的部分會被丟掉
- **起點錯開**:收到 0x07 時,時間值不是 0 的 slot 依 ID 順序輪流把 acc 起點設為 17 / 50 / 83
  - 同比例的 slot 會在不同 pulse 開啟,不會同時開
  - 起點平均 50,抵掉放開時丟掉的殘量
- freeflow 中 `0x00` 倒數暫停;`0x02` 結束 freeflow

**上位機實際流程**(K2 上位機 `aquivio-station`,2026-11 版):

1. 按下:送 `0x07`(不帶 UVC)
2. 出水中:每 250 ms 讀一次 `0x03` 流量
3. 到量或放開:送結束封包 `02 FF FF 03 00`
4. 讀流量,再送 `0x04` 歸零
5. 沖洗:送 `07 00 00`,之後再以 `0x02` 結束

同一杯放開再按，會重送同一包 0x07。

**已知行為**(同 K2,不修正):連續兩包 0x07 中間沒有 `0x02` 時，不會清除前一包的 slot 計時與已開的 slot。只會在結束封包遺失時發生。

## 5. 不支援功能的回覆格式 ⚠

K1 沒有的功能一律回 **9 byte**:`[4]` = 功能代碼,`[5..7]` = `FF [代碼] FF`。與 CS 錯誤(`FF FF FF FF`)可區分。

| 情況 | 回覆 |
|---|---|
| `0x08` 任何子命令(請求仍依 7 / 16 byte 收完) | `40 71 30 08 08 FF 08 FF 09` |
| `0x09` | `40 71 30 09 09 FF 09 FF 06` |
| `0x0A` | `40 71 30 0A 0A FF 0A FF 03` |
| `0xB0` | `40 71 30 B0 B0 FF B0 FF 11` |
| `0x03` 讀 ID18 以外 | `40 71 30 03 [ID] FF [ID] FF CS` |
| `0x06` / `0x07` Type ≥ 2 | `40 71 30 [06/07] [Type] FF [Type] FF CS`,例:`40 71 30 07 02 FF 02 FF 16` |

## 6. `0xB5` STATUS_QUERY(K1 自訂)⚠

K2 沒有此命令。用途是測試時確認輸出狀態，也能看出上位機下過什麼命令：序列埠看不到腳位，而 `0x00~0x02` 只回原封包。唯讀，不改任何輸出。

```
請求:40 71 30 B5 [SUB] 00 00 00 CS
例  :40 71 30 B5 00 00 00 00 6A
回覆:40 71 30 B5 [V0] [V1] [V2] [V3] CS       V = 32-bit,bit n = ID n
例  :40 71 30 B5 01 04 00 00 65               slot1 + 水泵開著(0x00000401)
```

| SUB | 回傳 |
|---|---|
| `00` | `Status`(程式記錄的狀態;無實體的 ID 11、16、17、25 也會顯示) |
| `01` | 實際腳位準位(讀暫存器;無實體的 ID 一律 0) |
| 其他 | `FF FF FF FF` |

正式版是否保留:〔待定〕。

## 7. 執行時序

- 收包、命令處理、回覆都在主迴圈;每 1 ms 的計時工作也在主迴圈補跑(見 [modules.md](modules.md))
- 收滿一包當場處理,回覆先進 TX 佇列(512 byte),不等待傳送
- `0x06` 的 pulse 倒數、freeflow 累積:每 1 ms 讀流量總計數的增量處理(K2 在流量計中斷內逐個處理,結果相同)
